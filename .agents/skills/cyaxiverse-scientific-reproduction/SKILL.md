# CYAxiverse Scientific Reproduction

1. Read `AGENTS.md`, the relevant source/status material, target implementation,
   and tests. Confirm the current branch/worktree state and preserve unrelated
   work.
2. Define the scientific program and claim before coding. Do not infer that two
   pipelines share a scientific measure merely because they share geometry
   inputs.
3. Record replay identity: immutable source/revision, selection route, counting
   unit, geometry/witness identity, basis/action convention, units, schema,
   software revision, relevant external-tool versions, and scale status.
4. For inflation, distinguish numerical homotopy from a physical divisor-volume
   transformation. Keep `scale_status=homotopy_only` until the joint physical
   map of divisor volumes, instanton data, kinetic metric, charges/phases,
   units, and domain constraints is derived and validated.
5. Validate progressively: analytic/synthetic contract, named source fixture,
   bounded reproduction, then predeclared population pilot/execution. Stop if
   source identity, counting unit, or an earlier gate fails.
6. Track selection effects, missingness, rejection, failure states, and coverage.
   Distinguish exact, branch-certified, finite-search, benchmark, filtered
   sample, and population-level claims.
7. Stop for scientific-owner direction when a paper convention, normalization,
   physical map, candidate classification, population definition, or reported
   estimand is ambiguous. Never tune acceptance logic merely to reproduce an
   expected count.
8. When delegated, continue ordinary investigation, debugging, correction, and
   retest loops without escalation. Escalate only at an existing
   scientific-owner or claim boundary. Final scientific evidence may be as
   detailed as required; the roughly 150-word limit applies only to a health
   `CHECKPOINT`. Keep large derivations and diagnostics in durable artifacts and
   return a concise manager-facing evidence packet with references.

Before handoff, run the applicable focused checks and broader repository gates,
and state exact commands/outcomes, claim boundary, source fingerprint,
`scale_status`, validation evidence, and unresolved limitations.
