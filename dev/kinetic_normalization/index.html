Kinetic normalization

This page states the axion kinetic normalization that CYAxiverse uses, how persisted outputs record it, and how outputs written under the earlier convention are read. The governing specification is CYAX-0232 (specs/0232-kinetic-normalization/spec.md, Issue #232).

The convention

Every physical axion path uses the kinetic matrix

\[K_{\rm kin} = 2\,\partial_T\partial_{\bar T}\mathcal{K} = 2\,\mathtt{Kinv}^{-1}\]

in

\[\mathcal{L}_{\rm kin} = -\tfrac12 M_{\rm pl}^2 K_{\rm kin}\,\partial\vartheta\,\partial\vartheta ,\]

where $\vartheta$ has period one and Kinv is the inverse Kähler metric $g^{-1}$ stored by CYTools. This is the literal $\mathcal N = 1$ supergravity normalization, written $c = 1$ in the common measure $\mathcal L_{\rm kin} = -c\,M_{\rm pl}^2 g\,\dot\vartheta\dot\vartheta$ with $g = \partial_T\partial_{\bar T}\mathcal K$ and $\mathcal K = -2\log\mathcal V$. CYAxiverse.KINETIC_NORMALIZATION == :sugra_c1 names it. Before CYAX-0232 the physical paths used $c = \tfrac12$.

Units: $M_{\rm pl}$ is the reduced Planck mass; masses are reported as log10(m/eV), decay constants as log10(f/GeV).

Shared functions.

  • kinetic_factor(Kinv) returns the canonical factor $B = \mathrm{cholesky}(\mathtt{Kinv}/2).L$, lower triangular with positive diagonal and $BB^T = \mathtt{Kinv}/2 = K_{\rm kin}^{-1}$.
  • kinetic_matrix(Kinv) returns $K_{\rm kin} = 2\,\mathrm{inv}(\mathtt{Kinv})$.
  • The kinetic norm of a charge column $q$ is $q^T(\mathtt{Kinv}/2)q$.

Every physical conversion of Kinv into kinetic data uses one of these. The factor ½ is applied only there. Every stored or exported inverse metric (Kinv, the Python inverse_metric, kinv in scripts) stays $g^{-1}$, and the potential uses $K^{a\bar b} = \mathtt{Kinv}$ unchanged.

Coordinates. $\vartheta = B\psi$ gives $\mathcal L_{\rm kin} = -\tfrac12 M_{\rm pl}^2\dot\psi^T\dot\psi$. A charge column $q$ maps to $\hat q = B^Tq$, and a ϑ-Hessian $H$ to $B^THB$.

K-argument contract. An API that takes a matrix argument named K (or documented as the kinetic matrix) takes the matrix in $-\tfrac12M_{\rm pl}^2K\,\partial\vartheta\partial\vartheta$ for period-one ϑ, and never rescales it. For stored CYTools data, pass CYAxiverse.kinetic_matrix(Kinv). An API that takes a canonical factor C takes one with $CC^T = K^{-1}$; CYAxiverse.kinetic_factor(Kinv) is such a factor. Results computed from a caller-supplied K are not labelled by the package.

read.K reads cytools/potential/K, which no repository writer produces. It is unlabelled and is not the physical kinetic-matrix accessor.

Open inferences (derived, not stated by the sources):

  • The published arXiv:2608.14780 numbers use $c = \tfrac12$: its Eq. 96 eigenvalues equal eig($g$), within 0.07 %, on the reconstructed N = 8 geometry.
  • The $K^{-1}$ of arXiv:2309.01831 Eq. 9 is $g^{-1}$, the CYTools Kinv: the F-term cross term derived with $K^{a\bar b}\mathcal K_{\bar b} = -2\tau^a$ reproduces Eq. 9 only with this identification.
  • The arXiv:2412.12012 numerics use $c = 1$: CYAX-0232 R-003 reproduces its Eq. 4.3 decay constant within 5 % at $c = 1$ and misses it by more than 20 % at $c = \tfrac12$.

Reproduction contracts

The reproduction paths for arXiv:2608.14780 (Issue #148, spec 0148) keep their own contracts and are numerically unchanged:

  • P96 (:p96_reproduction_c_half): $K_\theta = M_{96}/k^2$ with period-one θ, which is $c = \tfrac12$ because $M_{96} \approx g$. Used by paper_benchmarks reduced_models.jl, n8_continuation.jl and n8_g3_control.jl.
  • A96 (:a96_reproduction_raw_radian): the author's raw-radian $M_{96}/k^2$ (N8_K_RAW); in period-one coordinates $K_\theta = (2\pi)^2M_{96}/k^2$, about $c = 2\pi^2$. The same label covers the N = 5 author matrix N5_K_RAW. Used by poly102_inflation.jl, catastrophe_diagnostics.jl and the reproduction scripts.

Reproduction results that are structs or NamedTuples carry their label in kinetic_normalization; a result that mixes the two contracts carries kinetic_normalization_by_field instead. The persisted comparison CSV of scripts/inflation_reproduction.jl mixes them too: it has one <column>_kinetic_normalization label column for each value column and no row-level label. Functions that return a bare matrix, such as n5_kinetic_matrix and n8_kinetic_matrix, state their contract in their docstrings. Reproduction functions that use no kinetic matrix carry no label. Physical readers reject reproduction labels.

Reading earlier outputs

Outputs written before the change carry no label. They are read as :legacy_c_half with inferred = true only when their layout is recognized:

  • F1 at -3 without a label, or unversioned and holding every dataset physical_spectrum requires (optional datasets such as fpert_log10 do not matter; this includes data copied by migrate_legacy_spectra.jl);
  • F2 with spectrum/masses/log10 and no spectrum/metadata;
  • F3 at identity version 1 without a label;
  • F4 unversioned with total_model_count and model_mass_reference_log10_ev;
  • F5 at …-reproduction-1.2 without a label, or at 1.0 or 1.1 when the file matches one of the recorded historical layouts (specs/0232-kinetic-normalization/layouts/, scripts/f5_legacy_layouts_v10a.py, _v10b.py, _v11.py);
  • F6 at 2.3, 2.2, 2.1, 2.0 or 1.0 without a label (the group version is inflation/schema_version; the nested catastrophes/legacy_v1/schema_version marker is not it);
  • inflation CSV rows without the label column that match exactly one recorded historical entry (header, row_type, version values; see scripts/inflation_csv_labels.jl);
  • the unversioned F1 summary and F3 scan CSVs, and the earlier shard-merge-1.0 merges.

Readers raise an ArgumentError (Julia) or ValueError (Python) naming the file for a current version without a label, a label outside the table, a legacy version that carries a label, "legacy_c_half" or a reproduction label in a primary physical family, an F2 cubic_basis that is missing or unknown, and an unknown version or layout. These errors are never suppressed: existence checks and batch readers let them propagate.

Combining outputs. Any function that combines outputs across files, calls or rows rejects inputs whose labels differ, naming both. No conversion between conventions is provided.

Batch resume. A batch run never treats an output labelled or inferred as anything other than :sugra_c1 as complete. It is recomputed only under the runner's overwrite option (--force for batch_physical_spectrum.jl, force=true for run_batch_axion_photon and Pipeline 2); otherwise it is reported as failed (Pipeline 2: blocked) with the stored label. CSV writers refuse to append to a file whose header lacks the label column, and run_scale_continuation --resume refuses a report or shard file that holds earlier rows; the remedy is a new output path.

Migrations. migrate_legacy_spectra.jl and migrate_quartic_index_ordering.jl move values without recomputing them. They add no label or version and refuse a current-version target.

Notes on specific outputs

  • Earlier F2 cubic tensors are unreliable. Before CYAX-0232 both F2 writers called the cubic evaluator with mis-oriented instanton data, and an earlier F2 file records neither its writer nor its cubic basis. Readers report cubic_basis = :unknown for such files, and read.require_cubic_basis refuses them. Do not compare or rescale an earlier cubic tensor; recompute it.
  • Meaning of an inferred F5 label. For F5 files at 1.0 or 1.1 the label states the convention of the file's kinetic-matrix-dependent fields: the values the Julia model stage computes (model_stage.total_model_count, model_count_per_record, models[]) and fields derived from them, such as claim_status.model_count. Population counts, statuses, geometry and the stored inverse_metric do not depend on the convention. A file with no such field (no model stage) is still read as inferred legacy_c_half, so that combining it with current outputs fails closed: this records the file's provenance, not a statement that those values carry the earlier normalization.
  • Not certified. scripts/scan_fresh_relaxed_qcd_candidates.py passes kinv to a module that is not in the repository. CYAX-0232 does not certify its outputs under either convention, and it writes no label; physical readers treat its outputs as an unknown layout.
