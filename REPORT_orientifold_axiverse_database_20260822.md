## 2. Scope & scientific goal *(string theorist)*

The deliverable is a reproducible database, keyed by CY geometry, that pairs each inherited-orientifold trilayer class with its physical axion observables. The scientific frame is the KS/orientifold axiverse: closed-string axions from a Calabi–Yau hypersurface, with a scalar potential generated by Euclidean D-brane (instanton) contributions.

The **trilayer gate** (h¹¹₋ = 0 **and** h²¹₊ = 0) is the selection Sheridan et al. use for the census whose per-h¹¹ counts are 11 / 66 / 267 / 1033 (Table 1). Reproducing those counts exactly is the primary geometric validation of the selection stage.

Two independent physics programs are computed on each accepted geometry and kept **schema-separated** (they share only neutral geometry identities and readers, never a scientific bridge):

- **Spectrum program** — masses, decay constants, quartics (§5.1).
- **Vacua/inflation program** — vacuum counting, catastrophe classification, e-fold search (§5.2).

## 3. Geometry ingestion & selection *(string theorist)*

### 3.1 Source and identity
Geometries derive from a Kreuzer–Skarke polytope mirror (favorable polytopes, 05–10-vertex partitions for h¹¹ = 4/5) triangulated with CYTools. Each class carries a `polytope_id` (`lattice-points-sha256:…`) and a fine-triangulation hash `frst_hash`, so selection is content-addressed and replayable. One FRST per class is used.

### 3.2 Ledger provenance — a deliberate lower bound
The h¹¹ = 4/5 terminal orientifold ledgers (`h4.merged.json.zst`, `merged.json.zst`) are, by the handoff documents that produced them, **provisional, unreviewed lower bounds** — explicitly *not* certified Table 1 reproductions. Their `accepted_for_table_1` sets are conservative: classes whose orientifold smoothness evidence is `unavailable` are **never** promoted to accepted. The pipeline honors this: it does not treat the ledger's accepted set as the Table 1 count.

### 3.3 Certification of the gap
Re-deriving the exact `h21_plus_zero` diagnostic over the full population yields the Table 1 counts (267, 1033), which exceed the ledger's certified subset (260, 991). The differences (7 at h¹¹ = 4; 42 at h¹¹ = 5) are classes that satisfy h²¹₊ = 0 exactly but lacked a certified witness in the provisional ledger.

Each such class was run through the **actual** orientifold-smoothness / O3–O7 witness path (`find_accepted_o3o7_witness`, `scripts/build_orientifold_axion_database.py --stage certify-pending`), **not** hand-promoted:

- **h¹¹ = 4:** 7/7 certified (each earned `accepted_verified_orientifold` + `λ_f = 1`).
- **h¹¹ = 5:** 42/42 certified (`not_certified: []` in the run report).

Result: **all 1377 trilayer classes are witness-certified**, closing the gap to Table 1 at every level with genuine evidence.

## 4. Physical-point normalization *(string theorist)*

### 4.1 QCD volume-40 dilation
Each accepted geometry is dilated in Kähler moduli space to a canonical point where a chosen QCD divisor has **volume 40** (units of the string scale), giving a common, physically-motivated normalization across the database. The dilation is validated against the Kähler-cone and effective-cone constraints; if no stretched-cone ray achieves volume 40 for a candidate QCD divisor, that assignment is rejected (`NoQcdDivisorVolume`).

### 4.2 QED-divisor flagging
For each geometry the visible-sector search records whether an appropriate **QED divisor** intersecting the QCD divisor is present (`qed_charge_exact_match`, `qed_divisor_volume`, `qed_qcd_intersection`, …). This is **informational** (flagged, not required); a `QEDAssignmentFailure` on a given divisor is logged, not fatal.

### 4.3 Consequence: 2 QCD-volume-40 exclusions
Two h¹¹ = 5 classes — `poly_index=2957, class_index=2` and `poly_index=4539, class_index=5` — are witness-certified but have **no** prime toric divisor (of 9 candidates each) reaching QCD volume 40. They therefore produce no physical point and no `cyax.h5`. This is why 1033 certified maps to 1031 built. Both are recorded with per-divisor rejection reasons.

## 5. Physics pipelines *(string theorist)*

### 5.1 Pipeline 1 — axion spectrum
`scripts/batch_physical_spectrum.jl` (`--quartics`) computes, per geometry, from the charge matrix `Q (h¹¹×N)` and instanton scales `L (2×N)`:

- **Masses** `m` — eigenvalues of the axion mass matrix, stored as `log₁₀(m / eV)`.
- **Kinetic decay constant** `fK` and **perturbative decay constant** `fpert` — stored as `log₁₀(f / GeV)`. `fpert` includes the leading quartic self-coupling correction: `fpert = fK − ½·λ_self·log₁₀(e)` in log space.
- **Quartic couplings** (magnitude + sign + index tuples), from the quartic tensor:
  - `λ_self` — diagonal `(i,i,i,i)`, length = number of physical modes `n`.
  - `λ₃₁` — `(i,i,i,j)`, length `n(n−1)`.
  - `λ₂₂` — `(i,i,j,j)`, length `C(n,2)`.

The engine is the PQ-efficient hybrid (`pq_hybrid_physical_spectrum`) with a high-precision (256-bit) fallback for deeply suppressed instantons. The number of **physical** modes per geometry ranges 1…h¹¹ (some directions are removed as non-physical / too suppressed).

**Units caveat (flagged for review):** the HDF5 schema does not itself declare units. The eV (mass) vs GeV (decay-constant) assignment is inferred from the construction in `src/generate.jl`: masses carry a `+9` offset over decay constants, and the reduced Planck mass is `M_PLANCK_GEV = 2.435×10¹⁸` — i.e. the `+9` is the GeV→eV conversion. This inference is documented in the notebook's "Notes on units" cell and should be confirmed against the intended convention before the axis labels are treated as authoritative.

### 5.2 Pipeline 2 — vacua & inflation
`scripts/build_orientifold_vacua_inflation.jl` (`run_pipeline2(…; h11=N)`), per geometry:

- **Vacua** via the **reduced-JLM** engine with `method=:auto`. The default `:legacy` method throws a `BoundsError` on these deeply-suppressed-instanton geometries (instanton log₁₀ scales spanning roughly −111 to −654); `:auto` is used exclusively. Each result records `estimate`, `issquare`, `verified`, and a decision `threshold`. Across the database vacua are square (det = 1) and verified.
- **Catastrophes** via leading-critical-branch Hessian classification (`method = leading_critical_branch_hessian_classification`): `saddle_count`, `leading_minima_count`, `negative_mass_count`, `catastrophes_present`, `qtilde_det`.
- **E-folds** via bounded stationary-point refinement then gradient flow (`method = bounded_stationary_point_refinement_then_gradient_flow`): `n_candidates`, `n_qualified`, `n_flow_rows`, with numerical metadata (`max_efolds=60`, `min_efolds=50`, `precision_bits=256`, `flow_step=1e-3`, `flow_displacement=1e-8`, tolerances). Both search and refinement statuses are `completed`; coverage is `complete`.

**Finding:** across all 6283 geometries the e-fold search returns **0 candidates and 0 qualified trajectories at every h¹¹**. See §8.1 for interpretation and the scale caveat.

## 6. Software architecture & engineering *(software engineer)*

### 6.1 Data contract — `cyax.h5`
Path layout: `h11_XXX/np_YYYYYYY/cy_ZZZZZZZ/cyax.h5` (zero-padded). Top-level groups per file:

- `construction_metadata/` — canonical lattice points, face restriction.
- `cytools/geometric/` — Kähler data, `divisor_volumes`, `orientifold/` (involution, invariant/anti-invariant bases), `visible_sector/` (QCD/QED divisor indices, volumes, charges), and `potential/` with **`Q (h¹¹×N)`** and **`L (2×N)`**.
- `spectrum/physical/` — `m`, `fpert_log10`, `fK_log10`, `lambda_self_*`, `lambda_31_*`, `lambda_22_*`, `mode_indices`, `metadata/`.
- `vacua_pipeline/` — `estimate`, `issquare`, `verified`, `threshold`.
- `inflation/` — `catastrophes/`, `efolds/`, plus provenance (`git_revision`, `julia_version`, `schema_version=cyaxiverse-phase3-orientifold-inflation-1.0`, `completed_at`).
- `orientifold/` — `h11_minus`, `h11_plus`, `h21_plus`, `lambda_f`, involution/lattice matrices, torus-shift, and (for classes absent from the ledger) `pending_certification_json`.

**Matrix orientation is the single most safety-critical contract.** Julia's canonical shapes are `Q :: (h¹¹, N)` and `L :: (2, N)`. `HDF5.jl` reverses axis order relative to `h5py`, so on disk (written by the Python bridge) the arrays are transposed; the Python writer stores `q.T` / `l.T` so that the Julia readers see the canonical orientation. `L` rows are `[sign; log₁₀|Λ|]`. This is validated at the boundary and covered by regression tests.

All datasets are compressed (gzip level 9 / deflate 9), consistent with the repository's compression policy.

### 6.2 CLIs & idempotency
- Pipeline 1: `batch_physical_spectrum.jl --data-dir <root> --h11 N --quartics [--force] [--summary <csv>]`. Skips geometries already written unless `--force`; `--geometry H,P,F`, `--limit`, `--offset` for sharding.
- Pipeline 2: `run_pipeline2(<root>; h11=N)` — discovers geometries by walking the tree, **skips** any geometry that already has both `vacua_pipeline` and `inflation` groups (idempotent re-run).
- Bridge: `build_orientifold_axion_database.py --stage {select|full|certify-pending}` — `select` verifies counts and stops (hard-gate on Table 1 mismatch), `full` writes, `certify-pending` runs witness certification on named `(poly_index, class_index)` pairs.

Writes leave pre-existing groups intact; re-running Pipeline 1 with `--force` does not disturb `vacua_pipeline`/`inflation`, and vice versa (verified across all files after each re-run).

### 6.3 Provenance & replayability
Each inflation record stores the Julia version, git revision, schema version, method identifiers, solver metadata (tolerances, precision bits, step sizes, branch/point caps), and completion timestamp. Vacua records store the method (`:auto`), squareness, verification, and threshold. Geometry identity (`polytope_id`, `frst_hash`) is retained end-to-end.

### 6.4 Two engineering fixes made during the build
- **Type-stability bug (`src/generate.jl`).** Enabling `mixed_quartics=true` crashed at `physical_count == 1`: the quartic-index comprehension `[(i,i,i,j) for … if i≠j]` inferred `Vector{Any}` for the (always-empty) result, failing concrete-type dispatch downstream. Fixed by annotating the element type `NTuple{4,Int}[…]` at the affected call site and three textually-identical siblings. **Values are unchanged in every case**; only the container's inferred type changes. `Pkg.test()` green after the fix.
- **Over-strict shape check (`scripts/qed_divisor_assignment.py`).** A `prime.shape == effective.shape` equality guard rejected valid low-h¹¹ inputs where charge-row de-duplication legitimately yields different lengths. Removed with an explanatory comment; the previously-approved h¹¹ = 491 path (equal-length arrays) is unaffected. Regression tests added.

### 6.5 Tests, hygiene, versioning
- `Pkg.test()` passes — new testsets *Orientifold axiverse database bridge (Phase 1)* 45/45 and *Orientifold Pipeline 2 writing boundary* 27/27, plus all pre-existing suites (Tier-A optimisations, quartic-index migration, spectrum mode counts, …) green. Changes are additive; no test was weakened.
- `git diff --check` clean.
- **Version impact: minor** — new tooling and additive `lambda_31`/`lambda_22` HDF5 spectrum fields; no breaking change. Per `AGENTS.md`, feature branches state impact but do **not** bump `Project.toml`; the bump lands at the `vmm`→`main` release boundary. `Project.toml` remains `0.2.0`.

## 8. Caveats & limitations *(both referees — please read)*

1. **Zero qualified e-fold trajectories everywhere.** The e-fold search returns 0 candidates at all h¹¹. This is internally consistent (`candidate_slowroll_saddles = 0`) and physically plausible at these low h¹¹, but it is a *null* result and should be read as such, not as evidence that inflation is excluded.
2. **Inflation scale status is not explicitly recorded.** The `inflation/efolds/` group does **not** carry a `scale_status` field. The repository's own scientific policy distinguishes a *physical divisor-volume* path from a *numerical homotopy*, and cautions against reporting a homotopy crossing as a physical trajectory. Because the search found no candidates, no trajectory is *reported* as physical — but a referee should confirm whether the e-fold search operated on validated physical volumes or a numerical scale before this database's inflation leg is cited as a physical statement. **This is the single most important open scientific question in this report.**
3. **Units are inferred, not schema-declared** (§5.1). eV/GeV assignment comes from `src/generate.jl`, not from the HDF5 metadata. Confirm before treating axis labels as authoritative.
4. **Ledger provenance.** The h¹¹ = 4/5 base ledgers are provisional lower bounds; the Table 1 counts here rest on the independent O3/O7 witness certification (§3.3), not on the ledgers. The certification path re-derives witnesses rather than trusting the ledger's accepted set.
5. **Two structural QCD-volume-40 exclusions** (§4.3) — certified but not built; the database is 1375 classes, the certified census is 1377.
6. **Non-orientifold leg not built.** Both pipelines support a "without orientifold" path (h¹¹₋ = 0 only, or none), but the delivered database is specifically the inherited-orientifold trilayer set. A companion non-orientifold database is available on request but was out of scope here.
7. **Quartic-tensor storage.** Only `λ_self`, `λ₃₁`, `λ₂₂` families are persisted (not the full rank-4 tensor), which is what keeps per-file size ≈ constant.
